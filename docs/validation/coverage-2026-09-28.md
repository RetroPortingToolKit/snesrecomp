## Validated capture behavior

All nine desktop candidates build; applicable headless targets build too.
Twenty deterministic routes ran for 6,000 frames each with capture enabled
and disabled, totaling 240,000 simulated frames. Every final pair has matching
guest-state and video evidence. SMRPG additionally compares per-frame state,
master-cycle and SA-1 instruction traces. IoG and SMRPG compare host activity
counters. This validates capture behavior on these routes, not whole-game
correctness or the correctness of expanded generated code.

The enabled runs recorded 1,510,524,431 main-CPU instructions and separately
1,306,251,235 SA-1 instructions. All final captures ingest without warnings.
For each capture, the executable SHA-256 matches the tested binary; generated
program hashes match the original manifests where an AOT module exists.
Repeated checkpoint+journal imports produce identical counts. SimCity is an
explicit instruction-cost-only host, with no generated program to join.

## Promotion experiments and rejected claims

| Experiment | Generated AOT variants | Result |
| --- | --- | --- |
| Yoshi's Island | 621 → 642 | Replay diverges; first observed WRAM difference at frame 284 |
| BS F-Zero 2 | 45 → 162 | Replay diverges; register trace differs at frame 28, WRAM at 96 |
| SMRPG | 2 → 282 | Expanded build hits interpreter failure around frame 450; old address allowlist also fails on the new generated build |
| F-Zero, preserving historical roots | 468 → 459 | Input route matches with slightly more interpreted work; attract differs at WRAM $01F0 (9 versus 10), video matches |
| Illusion of Gaia | 0 → 167 | Expanded build becomes inactive at boot; only 12 logic changes and zero video changes |
| IoG, smaller groups | six groups of five hot entry addresses | Every group fails attract comparison; all-denied generated build exactly matches the baseline |

Earlier F-Zero generation accidentally replaced 231 historical roots with a
short attract profile. That experiment is invalid as an improvement comparison;
the corrected experiment retains the roots. Earlier IoG comparison used only
the final framebuffer and falsely appeared to show a 25.5% saving because both
runs ended black. Full state and activity checks reject it. No positive AOT
reduction from these experiments is release-qualified. Default title build
directories retain the original generated function bodies, with current capture
metadata. Failed expanded trees/binaries remain in separate experiment folders.

These findings separate discovery from code-generation correctness: observed
entry counts grow, but newly generated routines still need regression fixes.
Do not transfer an address allowlist to another generated/runtime build and
call it qualified. Increasing the static function count is insufficient.

## Save routes and visual inspection

Only SRAM save files were downloaded from
[FantasyAnime's Super Mario RPG saves](https://fantasyanime.com/squaresoft/mariorpg/mariorpg_saves.htm).
The report records their download URLs, sizes and SHA-256s. Each run receives
its own copy; player saves and the downloaded originals remain untouched.
Final images confirm the routes reached Moleville, Sunken Ship and the factory
area. The site's “BoosterTower” filename is a progression label, not the exact
spawn location. No ROMs or SRAM data are committed.

Visual review also confirms gameplay in Yoshi, both F-Zero titles and Gundam;
Mario Kart's input run reaches character selection, and SimCity reaches a city.
IoG's existing baseline input route ends black with no audio: it cannot be used
to claim full gameplay health even though enabling capture preserves its state.
Attract and basic fuzz routes do not exhaust the games.

The initial Star Fox script contained unsupported combined buttons; only the
corrected single-button routes count. The title's host now exports the presented
framebuffer for comparison. SimCity's existing cursor/View ROM patches change
the loaded-image hash; the corrected cases validate that patched identity.

Deep absolute save roots exposed a pre-existing 95-character truncation in
`RtlSetSaveRoot`. Earlier SMRPG long-path cases could fail to load the requested
save and are excluded. All final SRM cases use a short relative `saves` path
inside their isolated working directories, and match capture on/off exactly.
