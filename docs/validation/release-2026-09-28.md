# Coverage framework integration qualification

The owner approved Super Mario World, A Link to the Past, Super Metroid and
Mega Man X, including MMX's extended stage playtest and a separate Super
Metroid audio listening check. Further audio investigation is outside this
release's scope. The earlier measured sound-handshake differences remain
documented; listening acceptance is not a waveform-equivalence claim.

## Reproducible title inputs

Engine `2855081c174d89c968ab6c89a637a972d7c4b84c` installs automatic
`recomp/disassembly-layout.json` loading in the normal emitter and packaged
CLI. The three approved reference layouts contain addresses, instruction
lengths, data boundaries and source hashes, without ROM instruction bytes.
Generation verifies the owned ROM and reconstructs the validated constraints.

Fresh generation from each title's normal cfg directory, with no experimental
overlay or extra entry-mode flags, reproduces the complete approved analysis
manifest. Decoder audits retain zero conflicts. SMW's one byte-guarded WRAM
routine remains outside ROM authority. MMX's historical profile is explicitly
associated with its regional ROM; USA generation reproduces the same nodes and
exit facts. Regional Japan wiring is migrated but this playtest study is USA.

All four titles pin this framework plus its Linux capture portability fixes,
and the clean UI revision used by their
builds, `01bff9477e6847b2281260f0a9526a85e45b8ba2`. Super Metroid's two handwritten
fallback callers explicitly mark their already resolved handler entries under
the new API. Previous generated five-argument callers require full regeneration.

The two longer Super Metroid routes retain the same single intro APU timeout
each. The strict replay reports continue to reject that diagnostic; the owner
accepted the audio result after listening. No caps, scheduler bails or additional
runtime diagnostics appeared. Detailed hashes, identities and results are in
`release-2026-09-28.json`.

Validation: 512 focused Python checks; final native-generator Python checks
468 passed; Rust 88 library plus six binary tests; Rust formatting and Clippy;
packaged Windows CLI smoke including automatic disassembly layout ingestion.
The broad Windows Python run has 642 passes, two skips and two unrelated POSIX
scaffold assertions (execute permissions and MSYS/native path spelling).
Initial wrong-Python PATH failures were resolved using native Windows tools.
The release does not broaden into scaffold portability maintenance.

Linux CI subsequently passed all 646 Python tests. The complete Linux C runtime
suite passed locally after adding the capture module to the isolated command-line
harness, correcting the POSIX executable-path declaration/length comparison, and
updating the mod-comparison harness for its independent variant-registry boundary.
These follow-ups do not change the validated Windows gameplay path. Firmware-only
tests retain their documented skips when the optional DSP-1 image is absent.

Rust formatting and the equivalent reverse-iterator lint correction were
checked with the native tests; they do not change the runtime or AOT semantics.
Finite route comparisons and owner playtests qualify this change; they are not
independent hardware verification or proof of whole-game correctness.
