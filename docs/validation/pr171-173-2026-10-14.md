## Method and results

Each title uses the same title-main sources and UI revision in both arms.
Both native analyzers were built from their respective framework commits.
Every game was fully regenerated with the native backend and its normal
generation recipe before compiling a fresh Release executable. The tested
candidate executables are also the binaries staged for owner play.

Trace diagnostics are compiled out; finite replay capture records WRAM changes
each frame and final presented pixels, full WRAM, VRAM, CGRAM and PPU state.
The shared desktop hosts also record CPU registers each frame. All runs retain
rendering and enabled audio. These are functional comparisons, not performance
measurements or whole-game qualification.

| Game | Routes | Simulated frames per build | Result |
|---|---|---:|---|
| SMW | Attract, basic gameplay | 12,000 | All recorded evidence identical |
| ALttP | Attract, basic gameplay | 12,000 | All recorded evidence identical |
| Super Metroid | Attract, basic gameplay, Ceres/Ridley | 28,244 | CPU registers and all captured scenes identical; audio timing differences |
| Mega Man X | Attract, Highway | 24,000 | All recorded evidence identical |

Total: **76,244 simulated frames per build**, 152,488 across the paired runs.
No route reaches an interpreter cap or scheduler bailout. Super Metroid's long
intro retains one APU guest-clock synchronization timeout in each arm, as in
the earlier September qualification. The Ceres route's intro uses its recorded
turbo inputs; both arms simulate 16,244 frames and present 6,652 frames.

MMX's automated comparisons use SDL's dummy video driver with software
presentation and native audio, retaining full frame and device captures.
The first foreground-window attempt received a Pause input: a read-only probe
confirmed `g_paused=1`, with neither script quit nor script failure set. That
incomplete attempt is retained separately and excluded from results. Both
complete MMX routes were rerun without live keyboard input. Owner builds use
the normal desktop video driver and pacing.

MMX uses its pinned UI `41c88ffe`; the other three titles use `01bff947`.
An initial MMX configure used the older local UI, which lacks the current
title's netplay callback field; the dependency was corrected identically for
both arms before successful builds. No game source or framework fix was
needed for these test setup corrections.

## Super Metroid sound timing

Strict whole-trace equality remains **false** for all three SM routes:

| Route | Frames with WRAM differences | Different addresses | Sound command onset timing |
|---|---:|---|---|
| Attract | 4 / 6,000 | `$064B`, `$064F`, `$0652` | Same values, order and frames |
| Basic | 5 / 6,000 | `$064A`, `$064E`, `$0651` | Same values, order and frames |
| Ceres/Ridley | 174 / 16,244 | `$0643`, `$0645`, `$0649–$064B`, `$064D–$0652` | Same values and order per sound library; at most one frame shift |

The referenced SM disassembly's `variables.h` identifies these as sound queue
read positions, sound-library state, current sound and clear-delay bytes.
Every other WRAM byte matches each frame, including sound queue contents and
write positions. All CPU register fields match on every frame, and every
captured scene's full WRAM, pixels and video resources match exactly. An
additional same-binary baseline attract repeat matches its original evidence.

This resembles the previously documented aggregate AOT versus interpreter
audio-handshake timing class; this review does not establish its exact cause
or waveform equivalence. The current difference remains visible in the results.
Owner listening and gameplay acceptance is required before merging; a deeper
timing correction is separate work if the owner finds an audible regression.
